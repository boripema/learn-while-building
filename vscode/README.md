# Learn visual test 0.2.2

Click **Learn** in the VS Code status bar or run **Learn: Open visual learning tab**. One tab per window. Default: one visual step with actual, syntax-coloured source underneath, followed by an overview without repeated code. No branding header or token badge. The separate **Kaart** view offers bounded rendering, pan/zoom and whole-index file search.

The dot on Learn signals saved source changes without opening a view or indexing in the background. **Learn: Show local usage** reports view openings, visible minutes, step navigation and practice starts for this workspace. These local VS Code counters do not establish attention or learning. They are a first test of whether a separate page gets used. Nothing is added to Claude Code or Codex chat responses; no learning instructions reach main agents or subagents.

Optional Python completion exercises appear only for supported, standalone numeric return expressions. They use a restricted AST interpreter, never execute project code or mutate product files. Hints, reference solutions, counterexamples and feedback appear in the same view. Behaviourally matching alternatives can pass the finite tests; passing is not proof for every input or mastery. JS/TS exercises and general-purpose execution are not implemented.

Saved-code explanations are deterministic pattern templates, not personalised accounts of why an agent changed the product. Recognised provider imports are labelled as imports, not inferred runtime integrations. Static imports, heuristic roles and key-line selection can be incomplete or wrong. Aliases, dynamic dependencies, chat attribution and learner profiles remain unsupported. Pins prevent focus switching; the active source editor is a focus hint, not identification of the active chat.

Python 3 is required; configure `learnVisual.python` if needed. Changed files are reparsed locally with cache-version migration. Unsaved edits hide stale content until saved. Source changes invalidate the view before refreshing. When `learnVisual.autoRefreshOnSave` is false, refresh manually after saving. Hidden renderers unload, timers stop and indexers are cancelled. A shared scan lease permits one indexer across windows. Bounds: 64 KB/source, 2,000 files, 8 MB/project snapshot, 120 rendered local map nodes plus selected provider nodes. No browser, server, model or learning agent is launched by the extension.

The page follows VS Code surface colours and editor fonts; syntax uses highlight.js with Dark+/Light+ palettes, not exact custom TextMate/semantic token colours. Cytoscape.js (MIT) and highlight.js (BSD-3-Clause) are bundled locally with licences, no runtime CDN. Source and feedback stay in the local learning cache. No measured RAM target, causal whole-task ≤5% token result, or educational efficacy claim is made.

Design rationale: Mayer & Moreno (2003), DOI 10.1207/S15326985EP3801_6; Renkl et al. (2002), DOI 10.1080/00220970209599510; Shute (2008), DOI 10.3102/0034654307313795. Findings motivate segmentation, example fading and useful feedback; they do not validate this implementation or guarantee a Junior-to-CTO transition.

Module boundaries: VS Code host (`extension.js`), saved-source index/cache (`../hooks/visual.py`), pure exercise domain (`../hooks/practice.py`), pure visual templates (`web/mechanisms.js`), replaceable map renderer (`web/map.js`, mount/data/callbacks → fit/destroy), DOM/controller (`web/viewer.js`), styles (`web/viewer.css`), shell (`viewer.html`). The prepublish step copies the two Python sources into the package automatically. The controller still owns navigation and exercise forms; split further only when changes or tests justify it. Cytoscape objects stay entirely inside the map adapter. No framework or always-on service was added for modularity.
